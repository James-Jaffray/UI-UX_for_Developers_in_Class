


## Topic

# TYPES OF USER LIMITATIONS

- Visual impairments (blindness, low vision)
- Color blindness and dyslexia
- Hearing loss or deafness
- Motor or mobility challenges
- Cognitive, mental, or neurological conditions
- Aging-related impairments



# WCAG
Web Content Accessibility Guidelines
## Perceivable: Content must be presented in ways users can
perceive

## Operable:
Interface must be usable with various inputs
(keyboard, voice)
• Ability to control the Internet resource using the keyboard. Users
with physical disabilities may have difficulty pointing the cursor


## Understandable: 
Users must understand how to use the site
• Each element on the site or the intended action should be clear
to the visitor. This principle includes: the language switching
function, tooltips, clear separation of blocks

## Robust: 
Content must be compatible with assistive technologies
• Principle for the developer: When working on a website, it is
necessary to write clean code without additional lines and error


Each principle goes through 3 levels of testing that show whether the
standard has been met:
• **Level A:** Minimum accessibility
• **Level AA:** Mid-level (commonly required)
• **Level AAA:** Highest standard, most inclusive


## VISUAL IMPAIRMENTS (LOW VISION)

• Noticeable colour contrast: text should be brighter than the
background.
• Legible font and the ability to increase it on the site up to 200%.
• DO NOT justify the font.
• Possibility to change letter and line spacing.
• Control using the keyboard with the up and down buttons, as well
as the space bar and the Tab key.
• No captchas (tests that determine whether the user is a human or a
robot).
• No time restrictions: A visually impaired visitor will need more time to
explore the site.
• Audio accompaniment to text: the ability to listen to the entire site,
individual blocks, or transcripts of video fragments.
• Spell checking function, as well as hints on filling in fields.
• Prominent call-to-action buttons


# BLINDNESS

• Screen readers are special programs that read out all text
information on a website.
• No captcha or audio version.
• A clear page structure and division of material into paragraphs
with headings and subheadings so that the user can use screen
readers to find the material they need
• Audio transcription of images and video fragments.
• Hide unnecessary elements and tooltips from the screen
reader's field of vision that they can switch to.
• Arrangement of information in such a way that the user can
easily perceive the material by ear and clearly imagine the
structure of the site

# Color Blindness
- Avoid using color as the only way to convey information or call to
action.
- Possibility to customize the background and text color.
- High contrast so that the user can see the difference between
shades.
- text goes on blank background
- Underline links or highlight them in bold - making it easier to perceive
- **Contrast is Key**


# DYSLEXIA

- A legible font without serifs, italics, calligraphy or other letter
decorations.
- Create simple, short and clear sentences.
- Large indents between main blocks
- Ability to customize background color, text color and font size
- Add illustrations if you need to explain complex materia
- Don't use captcha: find other solutions for human recognition
- Avoid using italics, underlines, and capital letters - this is
confusing to the user
- Do not justify text.

# MOTOR DISABILITIES

• Touch control by voice or eye movement.
• Ability to use the site without a mouse.
• Keyboard control: commands should work by pressing a single key,
without complex combinations. This also includes scrolling.
• **Autofill: a must-have tool that will save the user from unnecessary
movements.**
• Increase the clickable buttons and the distance between them so that the
user does not experience difficulty when clicking



# COGNITIVE AND NEUROLOGICAL DISABILITIES

• Avoid loud and sudden sounds.
• The ability to independently turn off all audio accompaniments.
• Avoid frequent frame changes and unexpected flashes.
• The element cannot change its state more than 3 times per second, which
can cause an epileptic seizure.
• Build a simple and convenient navigation system to streamline decision-
making


# AUTISM SPECTRUM DISORDERS (ASD)

• Use simple and clear language without metaphors, complex
structures and artistic images that may be open to interpretation
• Avoid large amounts of information: short and concise texts.
• Eliminate flickering elements.
• Add subtitles to help the user better understand the material.
• Use breadcrumbs to allow the user to track their route


# COGNITIVE IMPAIRMENT AND DEMENTIA

• Use simple language without complex phraseological units.
• Minimize the number of choices available to the user.
• Create clear and easy navigation without unnecessary elements that
distract attention.
• Avoid long and complex blocks that are not separated by spaces and
images.
• Indicate the return path to the main page
• Use breadcrumbs to allow the user to track their route.
• Place the menu in the most visible place.
• Highlight important information in bold.
• Dilute the text with illustrations that will clearly explain the
material.

# INCLUSIVE DESIGN STRATEGIES

- Plan for accessibility from the beginning
- Consider a diverse range of users and context
- Use plain language
- Create flexible layouts
- Use descriptive labels and tooltips
- Test with real users of various abilities




# Key Takeaways

- Inclusive design improves usability for all
- WCAG provides guidelines to structure efforts
- Consider a wide spectrum of abilities, not just disability
